# 04 — An overnight crew for a repo you own

> **Why not just a Claude Skill?** Because it is 02:00 and you are asleep. A
> skill runs in a session you are present for; this runs every night for weeks.
> And the part that genuinely cannot be done in a session: when a run dies half
> way through opening a pull request, the **side-effect ledger** means the retry
> knows it already fired. No duplicate PR. A resumed chat has no idea.

**What you get:** a small, well-argued pull request most mornings, and a
diagnosis waiting for you when CI goes red overnight.

**What it teaches:** unattended operation over weeks, **attested evidence** from
GitHub, `controlled_domains`, and idempotent side effects.

**What you need:** your Anthropic API key **and a free GitHub account** with a
personal access token. This is the only example in the set that needs an
account, and it needs one because the whole point is doing something in the
world and proving it happened.

**Cost:** capped at $120/month — the highest in the set, because it works every
night.

---

## Set it up

**+ New project → Start from a setup file →** `04-an-overnight-crew.json`.

Then, before you start it:

1. **Point it at your repo.** Settings → Integrations → GitHub workspace. Use a
   repo you own and would not mind a bad PR on. The runner clones it into the
   sandbox at lease time, so work survives between runs.
2. **Fix `controlled_domains`.** It ships with `github:your-account` — replace
   `your-account` with your actual login. Read the next section for why this is
   not cosmetic.
3. **Wire the webhook.** Settings → Integrations prints a GitHub webhook URL and
   secret. Paste them into the repo's Settings → Webhooks. Now pushes, PRs and
   CI results arrive as evidence.
4. **Set your timezone** so 02:00 means 02:00 where you are.

## `controlled_domains` — the field that stops it marking its own homework

Anything on that list **cannot count as external evidence**.

Without it, the crew opens a PR, GitHub fires a webhook, and the platform
records "external evidence: activity on the repo" — evidence generated by the
project, about the project, counting as proof of outside interest. With your
login on the list, the platform sees `github:your-account` and refuses to count
it.

Which means when this project *does* show you external evidence, it is somebody
who is not you and not your agents. Set it correctly or the number is a lie you
told yourself.

## The rule that makes this safe to leave alone

Before any external action — opening a PR, pushing a branch, calling out — an
agent records it with `side_effect_begin` and a **stable idempotency key**. Then
it acts, then it calls `side_effect_finish`.

If the run dies in between, the janitor reaps the lease and releases the task,
and the *next* run's context pack contains the side-effect ledger for that task.
It reads "an attempt under key `pr-bump-requests-2` completed" and does not fire
again.

This is the difference between "an agent that can open a PR" and "an agent you
can leave running for a month". It is also why the goal says **never open a
second PR for something already open** — belt and braces on top of the ledger.

## What "done" looks like, per night

```json
{"type": "command",    "command": "cd /workspace && python3 -m unittest discover -q"}
{"type": "observable", "target": "each open PR changes one thing, with a title saying what and a body saying why"}
{"type": "observable", "target": "no PR is open for a change already covered by another open PR"}
```

The command test is the one that keeps you sane: **a red PR waiting in the
morning is worse than no PR**, so the suite runs before anything opens, and the
platform runs it — not the agent that wants to open the PR.

## What you'll see

- **Mornings.** One PR, sometimes none. "Nothing was worth doing" is an allowed
  and correct outcome; the goal says so explicitly, because the alternative is a
  crew that invents work to look busy.
- **A red main branch.** CI failure arrives by webhook, wakes the crew, and it
  outranks everything else — that is in the goal, and it is the behaviour worth
  having.
- **Activity → Runs at 02:00.** Runs you were not there for, each with its wake
  reason and its cost. This is what "it keeps working while you're away" looks
  like as a table.

## What to watch

- **Refactors nobody asked for.** The `engineer` charter forbids expanding
  scope, and the goal repeats it. Taste-driven restructuring of a repo you own
  is the failure mode here; kill those tasks and say so in the Boardroom.
- **Batched PRs.** One change per PR or you cannot review them at 8am, which is
  the whole point.
- **Spend.** $120 across a month of nightly work is roughly $4 a night. Watch
  the first week on the Overview's spend-by-team chart and tune
  `runs_per_project_per_day` before you touch the cap.
